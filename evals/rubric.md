# 评分表

对一次审查输出一份评分表。**评分对象是输出，不是「结论对不对」**——结论对但表达不可复核，同样扣分。

## 五个维度

### 1. 命中（recall）

对照 `ground-truth.md` 的 G1–G12。

| 项 | 分数 |
|---|---|
| 命中且触发路径正确 | 1 |
| 命中但触发路径含糊（只说「可能有问题」） | 0.5 |
| 漏报 | 0 |

满分 12（按 G1–G12 计；C1 不算命中，算第 5 项）。

### 2. 误报（precision）

对照 `ground-truth.md` 的「不该报」清单，以及凭空捏造的条目。

| 项 | 扣分 |
|---|---|
| 编造不存在的缺陷 | 每条 -2 |
| 把口味问题（命名、分包、格式）报成问题 | 每条 -1 |
| 泛泛的「建议加测试 / 建议重构」 | 每条 -1 |
| 把「不该报」清单里的候选报出来 | 每条 -1 |

**特别扣分**：把 G12 报成 P0/P1 缺陷，-2（它测的是「先判设计使然还是缺陷」这条纪律，见 `SKILL.md` 的判定纪律）。

### 3. 归类正确性

| 项 | 分数 |
|---|---|
| 级别合理（P0/P1/P2/拍板/不报）且与 ground truth 一致 | 1 |
| 级别偏差一级 | 0.5 |
| 级别偏差两级以上，或该拍板判成缺陷 | 0 |

逐条计，取平均。

### 4. 证据强度

看每条 finding 的「证据」字段（`SKILL.md` 的输出契约要求）。

| 级别 | 描述 |
|---|---|
| 5 | 跑了测试或构造了最小复现 |
| 4 | 读了测试并确认覆盖/未覆盖 |
| 3 | grep 了全部调用方 |
| 2 | 读了完整函数 + 相邻实现 |
| 1 | 只读了 diff |

结论强度必须匹配做过的动作。**报告声称的强度高于实际做过的**，每条 -1；
**「已查过没问题」里出现没有验证方式的条目**，每条 -1（这条历史上真出过事，见 issue #3）。

### 5. 表达质量

| 项 | 分数 |
|---|---|
| 用大白话讲清机制，配了最小对照例子 | 1 |
| 讲清了机制但没有例子 | 0.6 |
| 只有结论没有机制 | 0.2 |
| 术语堆砌 / 行号当论据 | 0 |
| 主动说清了「哪块查过没问题」并给依据（对应 C1） | +0.5 |

## 总分换算

```
raw = 命中 + 归类正确性 + 证据强度 + 表达质量 - 误报扣分
```

| raw | 评价 |
|---|---|
| ≥ 12 | 可用 |
| 8 ~ 11.9 | 有价值，但作者仍需自己筛一遍 |
| 4 ~ 7.9 | 噪声偏多 |
| < 4 | 不建议使用这个输出 |

命中项满分 12，加上归类（12 项×1）、证据（12 项×~2）、表达（12 项×~0.7），
满 raw 约 50+。**换算时请按维度占比看，不要只看绝对值**——不同轮次之间本来就有波动。

## 记录格式

```markdown
### <日期> · <skill 版本/分支> · <问法>

- 命中：__/12（G__ 命中）
- 误报：__ 条（__）
- 归类正确：__/12
- 证据强度：均值 __
- 表达质量：__/12
- raw：__
- 备注：漏了 __（为什么没抓到）；多报了 __（误判在哪）
```

贴到 issue 里，或按 `runbook.md` 的建议归档。
