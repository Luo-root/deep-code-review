# 评分表

对一次审查输出一份评分表。**评分对象是输出，不是「结论对不对」**——结论对但表达不可复核，同样扣分。

> **本表正文 + 文末「打分细则」是评分的唯一依据。** 细则把容易产生分歧的判据写死了，第三方照着它能复算出同样的分数。当前基线见 `evals/baseline.md`。

## 六个维度

### 1. 命中（recall）

对照 `ground-truth.md` 的 G1–G25。

| 项 | 分数 |
|---|---|
| 把该缺陷的实质说对了 | 1 |
| 只碰到一半，或明确否认它 | 0.5 |
| 完全没涉及 | 0 |

名义 25 条（按 G1–G25 计；C1 不算命中，算第 5 项），**有效满分 23**（见下方说明）。

> **有效分母是 23，不是 25。** G9 / G25 与 G3 同根因（GT「同一根因只算一次」），永远拿不到分——
> 所以 23/25 就是满分。读命中与归类的百分比时用 **23** 做分母，别把 23/25 当成 92% 的完成度。
> `raw` 里的 `N` 仍然是 25（GT 条目数），**不要改 N**——改了 raw 的量纲就变了，历史分数全部作废。

> **换样本时同步换口径**：本节写的是 tiny-shop（`evals/ground-truth.md`，G1–G25，N=25）。
> rule-engine 样本用 `evals/ground-truth-rule-engine.md`（R1–R10 里的 9 条，N=9），
> 判据完全一样，只是对照的条目文件与分母不同。

「说对了」的判定见文末细则一：独立成条、或作为别的条目里的一段正确陈述，都算 1。

**首轮基线用的是旧版 12 条口径**（见 `baseline.md`），与本表的 25 条**不可直接比较**。改 GT 之后必须重跑一轮评测，才能得到同口径的基线。

### 2. 误报（precision）

对照 `ground-truth.md` 的「不该报」清单，以及凭空捏造的条目。

| 项 | 扣分 |
|---|---|
| 编造不存在的缺陷 | 每条 -2 |
| 把口味问题（命名、分包、格式）报成**修复项** | 每条 -1 |
| 泛泛的「建议加测试 / 建议重构」报成**修复项** | 每条 -1 |
| 把「不该报」清单里的候选报成**修复项**（进必须修 / 建议修 / P3 等任何修复分层） | 每条 -1 |
| **快模式轮**：把既有问题（基线之前就存在）当本次引入报出 | 每条 -1 |

**「报成问题」= 进了修复分层**（必须修 / 建议修 / P3 等）。只放进「需要你拍板」或明确排除**不扣**——
口径以文末细则三为准。**同一条候选同时命中上面多行时只扣一次，不叠加**
（例：「不该报」清单里的「包名」既是口味问题、又在清单里 → 记 -1，不是 -2）。

**快模式轮的既有问题扣分**：快模式只报本次引入的问题。把基线之前就存在的问题报成 `[本次引入]`——
每条 -1，归属判定按 `ground-truth.md` 的「D 轮归属表」。**标 `[既有]` 的既有问题不扣分**，
不报也不扣——只有「判成本次引入」才是错。

**特别扣分**：把 G12 报成 P0/P1 缺陷，-2（它测的是「先判设计使然还是缺陷」这条纪律，见 `SKILL.md` 的判定纪律）。

### 3. 归类正确性

| 项 | 分数 |
|---|---|
| 级别落在 **GT 标注的允许级别集合**内 | 1 |
| 级别在集合外，但按 `SKILL.md` 的 P0–P3 定义自评只偏一级 | 0.5 |
| 级别偏两级以上，或该拍板判成缺陷 | 0 |

**先判「级别是否合理」，再看「与 GT 是否一致」。** 契约允许多级的条目（GT 标了允许级别集合的）
落在集合内就记 1，与 GT 表里那一个首选级别不同也不扣分——首选答案不是唯一答案。
GT 的级别集合见 `ground-truth.md` 与 `ground-truth-rule-engine.md` 的「允许级别集合」一节。

逐条计，取平均。**未报出的条目记 0**，所以这一项对漏报是二次惩罚——同时给出「按已报条目计」的辅助值，那个值更能反映判级能力本身。

**有效分母同样是 23**（G9 / G25 与 G3 同根因，见第 1 项的说明）——归类那 2 条也永远拿不到分。

### 4. 证据强度

看每条 finding 的「证据」字段（`SKILL.md` 的输出契约要求）。

| 级别 | 描述 |
|---|---|
| 6 | 读了 git 历史（能区分回归与既有问题） |
| 5 | 跑了测试或构造了最小复现 |
| 4 | 读了测试并确认覆盖/未覆盖 |
| 3 | grep 了全部调用方 |
| 2 | 读了完整函数 + 相邻实现 |
| 1 | 只读了 diff |

**无基线轮次拿不到第 1 级**——A / B / C 的裸目录样本没有 diff 可读，最低是第 2 级。这与 skill 自己的证据阶梯口径一致（`references/verification.md`：没有基线时从第 2 级起）。D 轮有 git 基线，第 1 级可达。

**第 6 级只有快模式轮（D 轮）可达**：D 轮有基线，报告读了 git 历史或对比了 base 才拿得到——
而「分清哪些是本次引入」正是快模式最核心的动作，也是 D 轮唯一不可被其他轮次替代的判别力。
没读历史就把既有问题报成本次引入的，这一级给不了，同时按误报维度扣分。

结论强度必须匹配做过的动作。**报告声称的强度高于实际做过的**，每条 -1；
**「已查过没问题」里出现没有验证方式的条目**，每条 -1（这条历史上真出过事，见 issue #3）。

### 5. 表达质量

| 项 | 分数 |
|---|---|
| 用大白话讲清机制，配了最小对照例子 | 1 |
| 讲清了机制但没有例子 | 0.6 |
| 只有结论没有机制 | 0.2 |
| 术语堆砌 / 行号当论据 | 0 |
| 主动说清了「哪块查过没问题」并给依据（对应 C1） | +0.5 |

### 6. 输出契约符合度（0–6，单列，不进 raw）

前五个维度评的是**审出了什么**；这一维评的是**按契约该长什么样**。
第 16–20 轮把输出契约改得越来越具体（覆盖表 15 行、五种取值、结论行五项计数、
三段标签、「宣称／实际」行、快模式固定栏位）——**这些改动在前五维里一条都测不到**，
所以单列一维，否则「改完变好了还是变坏了」仍然测的是旧能力。

| 项 | 1 | 0.5 | 0 |
|---|---|---|---|
| 覆盖表 15 行 | 行名与顺序全对 | 行名全对、顺序错 | 缺行，或行名不在规范集合里 |
| 结果格取值 | 全在五种之内，且 `n>0` 都带级别 | 取值合法但有 `n>0` 漏了级别 | 出现五种之外的写法 |
| 结论行五项计数 | 与正文条目逐级相等 | 差 1 项 | 差 ≥ 2 项，或多出第 6 个计数 |
| finding 标签 | 三段齐全，级别 / 维度 / 引入方式都合法 | 三段齐全但有 1 处级别或维度不合法 | 缺段，或引入方式段取值非法 |
| 「宣称／实际」行 | 存在且句式对（没有落差时写「宣称与实际一致」也算） | 存在但句式不符 | 缺这一行 |
| 骨架形态 | 七段齐全且顺序对（快模式轮：紧凑列表、**没有**七段骨架） | 段序错（快模式轮：出现七段骨架） | 缺段 |

**半分给「大致对但不精确」，0 分给「这条根本做不到」。**
0 分的项说明输出不符合自家契约——此时 raw 再高也不代表这份报告能用（下游按字段解析报告，形态不对就读不到）。

**这一维不进 raw**，理由是 raw 的量纲要保持稳定——raw 的口径（命中 / 归类 / 证据 / 表达）
从第一轮到现在没变过，契约改动改的是行为与结构。契约分单列，前后两版可以直接比。
> 读分提醒：契约分是**门槛**而不是加分项——0 分说明输出不符合自家契约，
> 此时 raw 再高也不代表这份报告能用（下游按字段解析报告，形态不对就读不到）。

## 总分换算

```
raw = 命中 + 归类合计 + 证据均值 × N + 表达合计 − 误报扣分
```

`N` = 该样本的 GT 条目数（tiny-shop 25 条 → N=25；rule-engine 9 条 → N=9）。

| raw | 评价 |
|---|---|
| ≥ 12 | 可用 |
| 8 ~ 11.9 | 有价值，但作者仍需自己筛一遍 |
| 4 ~ 7.9 | 噪声偏多 |
| < 4 | 不建议使用这个输出 |

命中项满分 N，加上归类（N 项×1）、证据（N 项×~2）、表达（N 项×~0.7），
满 raw 约 100+。**换算时请按维度占比看，不要只看绝对值**——不同轮次之间本来就有波动。

> **读分提醒**：证据项（均值×N）通常占 raw 的 70% 左右，单项独大。
> 轮次之间的 raw 差异，先看是「命中更多」还是「证据更硬」造成的。
> 另外**三个维度的实际分母不是 N**：表达与证据是按**报告交付的 finding 条目数**打分，
> 归类虽然按 N 条 GT 计和，但未报出的记 0，所以它同时受漏报拖累。
> 报告里必须同时写「合计」和「分母」，否则百分比没法复算。

## 判定：这一轮算不算通过

raw 衡量的是「审出了什么」，但**某个维度整体漏扫，在命中维度里完全看不见**——
「安全 / 可观测性 / 性能」这三个扩展维度在两份 GT 里都零条目，
skill 整个漏掉其中一维时，命中一条都不会少掉，raw 也不会掉。
所以放行要单独判，判据写死在这里：

| 条件 | 门槛 |
|---|---|
| 输出契约符合度 | 6 项**全得 1 分**，且覆盖表 15 行无缺行 |
| 命中 | ≥ 有效分母的 70%（tiny-shop ≥ 16.1 / 23；rule-engine ≥ 6.3 / 9） |
| 误报 | **0 条**（「不该报」清单里的候选报进修复分层、凭空编造的缺陷，都算） |

三条全过 = **通过**；任一条不过 = **不通过**，该轮不计入基线。
契约分是门槛不是加分项——这一节就是那个门槛的用法。

## 快模式轮（D 轮）判分

D 轮验证的是**快模式本身**：合并判定由这份 skill 直接给出，形态是紧凑列表，不套七段骨架。
前六维照常打，本节补的是**快模式特有**的判据；与第 6 维重合的形态项以第 6 维为准，不重复扣分。

**快模式轮不跑七维、不跑规模扫描、不跑反驳**——快模式契约里没有这三遍。
所以 D 轮的「命中」分母**不是**全部 GT 条目，而是 `ground-truth.md` 的「D 轮归属表」里
标着「本次引入」的那几条；其余是既有问题，快模式不报它们。

| 项 | 判据 | 不满足时 |
|---|---|---|
| 归属判定正确 | 本次引入的报 `[本次引入]`；既有问题不报，或报出来标 `[既有]` | 判成本次引入的每条 −1（误报维度） |
| 结论行计数 | `P0 n、P1 n、P2 n、P3 n、待拍板 n`；**零发现时不写数量** | 缺计数记 0.5；零发现时多写数量记 0.5 |
| 结尾有未覆盖行 | 「未覆盖：<…>」——抽样时必写抽样比例 | 缺这一行记 0.5 |
| 形态 | 紧凑列表（标题 + 3 行）；**没有**覆盖表、没有七段骨架 | 形态项由第 6 维判，本节不重复 |

**D 轮的 N 与 raw**：raw 里的 `N` 仍按该样本的 GT 条目数取（tiny-shop 25），不改——
D 轮与 A/B/C 轮的 raw 靠「归属表 + 分母」区分，不靠改量纲。

# 打分细则（歧义点定死版）

正文里写得含糊、每轮都会吵起来的地方，在这里定死。**打分时以本节为准。**

## 一、命中（recall，名义 25 条 / 有效满分 23）

| 情形 | 分数 |
|---|---|
| 把该缺陷的**实质说对了**——独立成条，或作为别的条目/覆盖表里的一段正确陈述 | 1 |
| 只碰到一半（只陈述了相邻事实、没把它说成该缺陷）；或明确否认它（声明它「不算问题」） | 0.5 |
| 完全没涉及 | 0 |

补充：

- **C1 不占命中**，它算表达质量的正向加分。
- **同一根因只算一次**：折扣能力整体没接线（G3 / G9 / G25）只记最靠前的一条（G3），**命中与归类都不再计分**。
- 「明确否认」与「没涉及」要分清：**报告讨论了这个缺陷的实质并判定它不是问题 → 0.5**；报告压根没谈这个方向 → 0。
  - 例（A 轮、B 轮）：写「模块内也没有任何 IO 调用／没有存储写入路径，承诺成立」——这是 G4 事实的一半（模块里确实没有存储），但结论是「承诺没问题」而非「承诺没有对应对象」→ **命中 0.5、归类 0**。
  - 例（A 轮）：在「本次没覆盖」里写「这 4 个文件是纯内存实现，持久化……不在本次范围内」——碰到了 G22 的相邻事实（没有持久化层），但把它划到范围外、没说这是缺陷 → **命中 0.5、归类 0**。
  - 例（C 轮）：只写「godoc 里的只读承诺会让人以为 `Run` 是纯函数」——那是 G4 的镜像问题（承诺低估了副作用），没问「承诺指向的对象在不在」→ **G4 记 0**。
- **只是引用了相关代码/文档但没评估那条性质** → 0。例如 B 轮写「与 `refund.go:24-26` 的文档一致」，那是引用 G19 那段注释去背书幂等语义，没有核对「第二个返回值」的说法 → **G19 记 0**。

## 二、归类正确性（名义 25 条 / 有效满分 23）

| 情形 | 分数 |
|---|---|
| 该条目拿到了自己的级别，且落在 GT 标注的**允许级别集合**内 | 1 |
| 级别在集合外，但按 `SKILL.md` 的 P0–P3 定义看只偏一级 | 0.5 |
| 级别偏两级及以上 | 0 |
| 没有自己的级别（只在别的条目里被顺带提到），但宿主条目级别落在允许集合内 | 0.5 |
| 没有自己的级别，且宿主条目级别不在允许集合内 | 0 |
| GT 说「该拍板」而报告判成缺陷 | 0 |
| GT 说是缺陷（P 级）而报告判成「需要你拍板」 | 0.5 |

补充：

- **GT 的级别是首选答案，不是唯一答案。** GT 标了「允许级别集合」的条目（见 `ground-truth.md` 与
  `ground-truth-rule-engine.md` 的「允许级别集合」一节），落在集合内即记 1——与 GT 表里那一个
  首选级别不同也不扣分。契约里 P1 与 P2 的定义本来就覆盖同一批事实
  （「在可预测的真实输入下出错」vs「持续制造维护成本」），同一个缺陷判 P1 还是 P2
  有时是判据本身的噪声，不是能力差——把这种噪声算进分数，测出来的就不是判级能力。
- **未报出的条目记 0**，所以这一项对漏报是二次惩罚。
- **「按已报条目」的辅助值 = 归类合计 ÷ 报告交付的 finding 条目数**
  （finding 条目数 = 必须修 + 建议修 + 拍板项；**不含**「已查过没问题」「本次没覆盖」）。
- 另可给一个更贴近判级能力的辅助值：**归类合计 ÷ 命中条目数**（命中 ≥ 0.5 的 GT 条目数）。

## 三、误报（precision）

| 情形 | 扣分 |
|---|---|
| 编造不存在的缺陷 | 每条 −2 |
| 把「不该报」清单里的候选报成**修复项**（进必须修 / 建议修 / P3 等任何修复分层） | 每条 −1 |
| 把口味问题（命名 / 分包 / 格式）报成**修复项** | 每条 −1 |
| 泛泛的「建议加测试 / 建议重构」报成**修复项** | 每条 −1 |
| 只把它放进「需要你拍板」，或明确排除 | 不扣 |

**正文那几行是本节的概括，与本节冲突时以本节为准。**
**同一条候选命中多行只扣一次，不叠加**——例：「不该报」清单里的「包名」既是口味问题、
又在清单里 → 记 −1，不是 −2；「泛泛建议补测试」同理。

**GT 之外的真实问题**：不扣分、不加分（它不是误报，只是不在 GT 里）。
**漏报**在误报这一项**不扣分**，它在命中和归类两处已经计过了。

## 四、三条特例

1. **同一根因只算一次**：折扣能力整体没接线（G3 / G9 / G25）只记最靠前的一条（G3），其余**命中与归类都记 0**。
2. **G12**（`Percent` 无范围校验，GT 要求进「需要你拍板」）：
   - 独立拍板项 + 给了两条路 + 建议 + 要你定什么 → 归类 1
   - 在别的拍板项里顺带提到（给了具体触发与修法） → 归类 0.5
   - 作为缺陷条目报出 → 归类 0
   - 明确排除（「等某个决策定了再一并处理」） → 命中 0.5、归类 0
3. **G13**（退款窗口从查询时刻起算）：判成 bug 或判成拍板**都算命中**；
   若报告把它说成「已经确认的 bug」，且**没有把「退款窗口该不该有 / 该由谁定」作为需要回答的问题提出来** → 归类 0.5。
   - 判据：报告里出现「这个 24 小时是全平台统一口径，还是按商户/渠道/品类区分」这类**需要用户或业务来定的问题**（写在拍板项里或明确提问）→ 归类 1；
     只是说它是「业务政策值」、应该做成参数或配置项 → **不算**谈业务前提，归类 0.5。

## 五、证据强度（1–6 级，取均值）

| 级 | 含义 |
|---|---|
| 6 | 读了 git 历史（能区分回归与既有问题）——**只有 D 轮可达** |
| 5 | 跑了测试 / 构造了最小复现 |
| 4 | 读了测试并确认覆盖或未覆盖 |
| 3 | grep 了全部调用方 |
| 2 | 读了完整函数 + 相邻实现 |
| 1 | 只读了 diff |

- 取**全部上报条目**（含拍板项）的均值。
- **无基线轮次最低记 2 级**（没有 diff 可读）；D 轮有 git 基线，第 1 级可达。
- 声称强度高于实际做过的，每条 −1。
- 「已查过没问题」里没有验证方式的，每条 −1。
- **一条目的级别看它「中心主张」的验证强度**：该主张自己写在条目里的探针/实测算；
  同一份报告里已经为该主张**确立了前提**的探针也算（条目明引，或事实同一）。
  反过来，条目只是复述别处跑过的、与该主张无关的探针，不给分。
- **必须逐条列出明细**（哪条几分），否则不可复算。

## 六、表达质量（满分 = finding 条目数 + 0.5）

| 情形 | 分数 |
|---|---|
| 用大白话讲清机制且配了最小对照例子 | 1 |
| 讲清机制没例子 | 0.6 |
| 只有结论 | 0.2 |
| 术语堆砌 / 行号当论据 | 0 |

- 拍板项另加一条要求：给了「两条路 + 建议 + 要你定什么」才记 1。
- 主动说清「哪块查过没问题」并给依据（对应 C1）→ 额外 +0.5。
- **「最小对照例子」的判据**：报告里能指认一个**可复现的具体症状或并置对照**，二者之一即可——
  - 可复现的输入/输出（探针数字，如 `0.29 元 → 结算 28 分 / 退款 29 分`、`NaN → total=-9223372036854775808`）；
  - 「这里声明/承诺了什么」与「实际发生了什么」的并置（如「总=0 但 Processed=1」对上「期望 total=0、计数为 0」）。
  - 只有**静态断言 + 场景描述**（如「grep 全仓零调用点 + 想接入第二种策略时才发现这个抽象没在管事」、
    「`timeout` 只出现在签名那一行 + 调用方以为这批最多跑 1 秒」）→ **0.6**。
- **必须逐条列出明细**。

## 七、raw

```
raw = 命中 + 归类合计 + 证据均值 × N + 表达合计 − 误报扣分
```

其中 **N = 该样本的 GT 条目数**（tiny-shop 25 条口径 → N=25；rule-engine v2 口径 9 条 → N=9）。

> **为什么 N 要跟着样本走**：证据均值是个 1–6 的小量级，不乘一个分母就淹没在 raw 里。乘 N 是为了让它和命中、归类、表达在同一量级上可比。**因此不同样本的 raw 不可直接比较**——tiny-shop 的 163 和 rule-engine 的 raw 相差部分来自 N 不同，比较时必须看维度占比。

> **读分提醒**：证据项（均值×N）通常占 raw 的 70% 左右，单项独大。
> 不要只看 raw 总数，要看维度占比（命中/N、归类/N、证据 1–6、表达/条目数）。

## 八、这套细则与首轮打分的口径差异

首轮（12 条口径）用的是「只在证据里点到记 0.5」的旧写法。本细则改成
「**命中 1 = 实质是否说对**」，独立成条或在别的条目里顺带说对都算 1。
因此**首轮分数与本细则下的分数不可直接比较**，要比较必须按同一细则重跑。
